# Architectural Decision Records (ADRs)

This document records the principal architectural decisions made for the SumaqAgro frontend application (Angular 22 web application of the SumaqAgro Platform).

---

## ADR 001: Adoption of Domain-Driven Design (DDD) and Screaming Architecture

### Status
Accepted

### Context
The application serves three segments (agricultural producers, cooperative directors, and agronomists) across several business capabilities: identity, cooperative profiles, subscriptions and payments, field management, crop health, and harvest certification. It must scale while keeping high cohesion, low coupling, and the same boundaries as the RESTful API.

### Decision
Structure the frontend codebase according to Domain-Driven Design (DDD) tactical patterns and bounded contexts that mirror the backend:
- **Bounded Contexts**: `iam`, `profiles`, `subscriptions`, `farming` (Field Management), `crop` (Crop Health), `certification` (Harvest Certification), and `shared`.
- **Layered Architecture per Context**:
  - `domain/model`: Pure domain entities, value types, and commands (`entities/`, `commands/`) free from framework dependencies.
  - `infrastructure`: API facades, endpoint adapters, assemblers, request/response DTOs, guards, and interceptors.
  - `application`: Signal-based state management stores.
  - `presentation`: UI components and views; each context exposes its own `*.routes.ts`.

### Consequences
- **Positive**: Clear boundaries between domains, one-to-one alignment with the backend bounded contexts, high maintainability, and isolated testing.
- **Negative**: Additional boilerplate for mapping between layers (assemblers, requests, and responses).

## ADR 002: Signal-Based State Management for Application Stores

### Status
Accepted

### Context
State management in modern Angular applications requires fine-grained reactivity, optimal change detection, predictable state mutations, and minimal boilerplate. The application is zoneless (no `zone.js` dependency), so the UI must react to signal changes.

### Decision
Use lightweight, domain-scoped application stores (`IamStore`, `ProfilesStore`, `SubscriptionsStore`, `FarmingStore`, `CropStore`, `CertificationStore`, and `LayoutStore` in `shared`) powered by Angular Signals (`signal`, `WritableSignal`, `computed`, and `inject()`):
- Internal mutable state is kept private via `WritableSignal` (e.g., `currentUserSignal`, `loadingSignal`, `errorSignal`).
- Public state is exposed as read-only `Signal` accessors through `asReadonly()` and derived state through `computed()` (e.g., `isSignedIn`, `activeUser`).
- Asynchronous API interactions update signal state reactively, including loading and error states typed as string unions (e.g., `IamError`).

### Consequences
- **Positive**: Integrates natively with Angular's zoneless signal reactivity; removes external state library dependencies.
- **Negative**: Developers must follow conventions for managing immutable state updates inside store methods.

## ADR 003: Assembler Pattern and Layered REST Infrastructure

### Status
Accepted

### Context
API contracts (backend resources/responses) differ from internal frontend domain models in naming conventions, structure, or data types (e.g., backend roles `ROLE_FARMER` vs. frontend `FARMER`, ISO date strings vs. `Date`).

### Decision
Implement the Assembler pattern using generic base infrastructure abstractions in `shared/infrastructure`:
- `BaseEntity`: Base class for domain entities with an identifier.
- `BaseResource` / `BaseResponse`: Contract for wire DTOs; each context also defines `requests/` for request bodies.
- `BaseAssembler<TEntity, TResource, TResponse>`: Pure transformation interface translating between DTOs and domain entities; assemblers also translate commands into requests (e.g., `SignInAssembler.toRequestFromCommand`).
- `BaseApiEndpoint`: Generic HTTP endpoint wrapper providing CRUD operations and unified error handling (`ErrorHandlingEnabledBaseType`).
- `BaseApi`: Facade composing one or more endpoint classes for application consumption (e.g., `IamApi`, `FarmingApi`).
- Endpoint URLs are composed from `environment.platformProviderApiBaseUrl` and one `platformProvider*EndpointPath` per resource.

### Consequences
- **Positive**: Decouples domain logic from backend schema changes; standardizes CRUD operations and error handling across endpoints.
- **Negative**: Requires writing assembler classes for every resource entity.

## ADR 004: Material 3 (M3) Theming System and Centralized Overrides

### Status
Accepted

### Context
The application requires a modern, accessible, and customizable UI component library with the SumaqAgro brand colors.

### Decision
Adopt Angular Material with Material 3 (M3) theming:
- Use `@use '@angular/material' as mat;` and the `@include mat.theme(...)` API with custom palettes generated by `ng generate @angular/material:theme-color` (`src/_theme-colors.scss`): primary `#286643` (field green) and tertiary `#9A7B2F` (harvest gold), Poppins typography.
- Leverage system-level design tokens (`var(--mat-sys-surface-container-low)`, `var(--mat-sys-on-surface)`).
- Use the Material Symbols Outlined font for `<mat-icon>` (registered in `app.config.ts`).
- Style entrypoints referenced in `angular.json` styles configuration (`src/material-theme.scss`, `src/styles.css`, and the Leaflet stylesheet).

### Consequences
- **Positive**: Modern UI/UX, built-in accessibility (a11y), responsive token variables, and consistent design language.
- **Negative**: Requires familiarity with Material 3 token naming conventions and Sass mixin APIs.

## ADR 005: Standalone Components Architecture and Lazy-Loaded Routes per Bounded Context

### Status
Accepted

### Context
Angular standalone components eliminate `NgModule` boilerplate. With six bounded contexts, loading every view at startup would make the first load slow on rural mobile connections.

### Decision
- All components, directives, and pipes are standalone (default in Angular 22). Dependencies and Material modules are imported directly in `@Component.imports`.
- Each bounded context exposes its own `*.routes.ts`, loaded with `loadChildren`/`loadComponent` from `app.routes.ts`.
- Chart.js is only provided (`provideCharts(withDefaultRegisterables())`) on the dashboard routes that draw charts.

### Consequences
- **Positive**: Tree-shakable bundle sizes, explicit dependency declaration, simplified testing setup, and lazy loading per context.
- **Negative**: Each component must explicitly list its imported dependencies.

## ADR 006: Internationalization (i18n) via `@ngx-translate`

### Status
Accepted

### Context
The application must support English and Spanish with runtime language switching without full page reloads, including dates and numbers formatted for Peru.

### Decision
Use `@ngx-translate/core` and `@ngx-translate/http-loader` with one translation file per bounded context in `public/i18n/{lang}/` (`shared.json`, `iam.json`, `profiles.json`, `subscriptions.json`, `farming.json`, `crop.json`, `certification.json`):
- Multi-file loader (`provideTranslateMultiHttpLoader`) configured in `app.config.ts`, with English as fallback.
- `LanguageSwitcher` shared component allows user-driven language toggling at runtime.
- `TranslatedTitleStrategy` translates the browser tab title of each route.
- Spanish (Peru) locale data (`es-PE`) is registered for Angular date and number pipes.

### Consequences
- **Positive**: Dynamic, client-side translation switching without page reload; each bounded context owns its translation keys.
- **Negative**: Async loading of translation files requires handling initial translation initialization; a new bounded context must be added to `TRANSLATION_FILES`.

## ADR 007: TypeScript ES2022 Target and Modern ECMAScript Features

### Status
Accepted

### Context
Modern browsers and the Angular build pipeline (esbuild / Vite) support modern JavaScript features natively, reducing polyfill overhead and improving execution performance.

### Decision
Configure `tsconfig.json` compiler options targeting `ES2022` with `module: "preserve"`, TypeScript 6, and strict checks (`noImplicitOverride`, `noImplicitReturns`, `noPropertyAccessFromIndexSignature`, strict Angular injection and input access modifiers).

### Consequences
- **Positive**: Generates smaller, cleaner JS bundles; unlocks class fields, top-level await, and `Array.prototype.at`.
- **Negative**: Requires modern browser support (aligned with the Angular 22 browser baseline).

## ADR 008: Functional Guards and HTTP Interceptor for Session, Role, and Subscription Access

### Status
Accepted

### Context
Private pages must only open for signed-in users, each role must stay inside the pages of its own segment, and the paid features require an active subscription. Every API call must carry the JWT.

### Decision
- `iamInterceptor` (`HttpInterceptorFn`) adds `Authorization: Bearer <token>` from `IamStore` to every request.
- `iamGuard` (`CanActivateFn & CanActivateChildFn`) redirects visitors without a session to `/iam/sign-in`.
- `roleGuard` (`CanActivateChildFn`) sends a role that opens a page of another segment back to its own start page (`/dashboard`, `/cooperative/dashboard`, or `/pest-reports`).
- `activeSubscriptionGuard` (`CanActivateChildFn`) asks the backend for the current subscription and sends users without access to `/subscriptions/plans`.
- The session (token and user) is kept in `localStorage` and cleared when the JWT expires.

### Consequences
- **Positive**: Access rules live in one place per concern and are reused by every route; the backend still enforces authorization.
- **Negative**: Guards depend on `IamStore` state being restored before navigation.

## ADR 009: Offline Queue for Campaign Expenses

### Status
Accepted

### Context
Producers record field expenses in rural areas with intermittent connectivity. Losing an expense because the signal dropped would make the campaign cost ledger and breakeven price unreliable.

### Decision
- `OfflineSync` (`farming/infrastructure/offline`) tracks `navigator.onLine` with a signal and stores `PendingOperation` items in `localStorage`.
- `FarmingStore` queues expenses while offline and sends them when the connection returns.
- Each queued expense carries a `clientSyncId`, so the backend records it only once even if it is sent twice.

### Consequences
- **Positive**: Expenses are never lost; the user sees how many operations are pending.
- **Negative**: Only expenses are queued; other operations still require a connection.

## ADR 010: Mercado Pago Checkout Pro through a Backend-Created Redirect

### Status
Accepted

### Context
Subscription plans are charged with Mercado Pago. Payment credentials and the Mercado Pago access token must never reach the browser.

### Decision
- The web application never calls Mercado Pago. It asks the backend for a checkout session (`POST /subscriptions/me/checkout-sessions`) and receives a `PaymentCheckout` with its `checkoutUrl`.
- The `Checkout` view redirects with `document.location.assign(checkoutUrl)`; when Mercado Pago returns, the payment result view asks the backend to confirm the payment.

### Consequences
- **Positive**: No payment secrets in the frontend; the backend verifies every payment with Mercado Pago.
- **Negative**: The user leaves the application during payment and the result depends on the redirect back.

## ADR 011: Leaflet Maps, Chart.js Charts, and Client-Side Documents

### Status
Accepted

### Context
Producers draw plot boundaries and see NDVI/NDWI imagery on a map, dashboards show costs and vegetation trends, and cost reports must be downloadable without adding heavy dependencies.

### Decision
- Use Leaflet for plot boundary drawing and polygon viewers (`PlotBoundaryMap`, `PlotPolygonViewer`, `CropHealth`).
- Use Chart.js through `ng2-charts` for dashboard charts (`CostDistributionCard`, `NdviChartCard`).
- Generate simple PDF documents (campaign cost reports and payment receipts) in the browser with the shared `text-pdf` helper and save them with `FileDownloader`; quality certificates are downloaded as PDFs generated by the backend.

### Consequences
- **Positive**: Open-source, lightweight libraries without paid map or chart services.
- **Negative**: Leaflet and Chart.js are imperative libraries that must be wrapped carefully in components.
